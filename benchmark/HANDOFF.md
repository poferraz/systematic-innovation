# External-agent operating brief

Read `../AGENTS.md`, `../CONTEXT.md`, both approved specifications, and applicable component plans. `skills/systematic-innovation/` is frozen. This handoff authorizes offline fixtures and approved public execution only; it does not authorize live study spending, private-pack access, publication, merging, or pushing.

1. Verify CPython 3.13 and uv 0.12.8. From `benchmark/`, run `uv sync --locked`, `uv lock --check`, `uv run --locked pytest -q`, `uv run --locked ruff check .`, and `uv run --locked mypy src task9`. Run the root standard-library tests and repository validator too.
2. Validate the explicit configuration with `uv run --locked sib validate --config CONFIG`. Inspect models/hosts/allowlists, environment names, per-turn cost ceilings, maximum calls/cost/concurrency/retries, and failure threshold. Never put credential values in YAML, command arguments, JSONL, or reports.
3. Make a bounded dry plan: `uv run --locked sib plan --config CONFIG --cases cases/development --case-ids CASE_IDS --run-dir RUN --dry-run`. Reject unknown, duplicate, or empty case IDs. A new run uses a fresh ID/directory. Unknown price means unknown planned cost, never zero; execution requires a declared ceiling. This planning step makes no model call.
4. For a reviewed subprocess, use `uv run --locked sib run --config CONFIG --cases cases/development --case-ids CASE_IDS --run-dir RUN`. The argument array and resolved executable must be allowlisted; the environment is filtered, capture bounded, and timeout enforced. An independent OS sandbox controls filesystem/egress. The offline example is in README.md.
5. For inbox exchange, `uv run --locked sib plan --config CONFIG --cases cases/development --run-dir RUN`, then `uv run --locked sib export --run-dir RUN --output RUN/outbox-1.jsonl`. Give only exported opaque TurnJobs to generators. Return exactly one assistant turn for the requested identity/index/attempt. Process each opaque turn ID once. Never modify prior transcripts, disclosure order, model parameters, or instructions. Never inspect source mappings, another treatment's answers, rubrics, hidden labels, or judgment packets while generating.
6. `uv run --locked sib ingest --run-dir RUN --input RETURNED_JSONL` validates and redacts before append-only canonical storage. Identical re-ingestion is idempotent; replacement is refused. Repeat export/ingest for pending turns only. `uv run --locked sib resume --run-dir RUN` reconstructs the next turn, never regenerates successful turns, and stops on unresolved dispatches rather than spending twice. Keep external response files under the same custody as prompts; never commit them.
7. Verify `uv run --locked sib verify-run --run-dir RUN`. Every Deep treatment must have identical ordered user disclosures; questions and all other assistant turns remain in the denominator. Only the last portfolio supplies candidate mechanisms. Do not substitute final-answer or estimated token counts for unknown complete accounting.
8. `uv run --locked sib score --run-dir RUN` preserves unrated candidates; it cannot fabricate human usefulness. A separate measurement role may supply `--judgments SCORE_JSONL` with structured extractions, anchored quality evidence, judge identity and reviewed semantic-equivalence evidence. Never use generator self-ratings. Quality gate first, then cluster qualifying candidates. Judge libraries construct seeded randomized, both-order blinded jobs and separate mechanism-quality packets. Store private assignment keys outside rater access. Follow study/human-calibration.md: minimum 40 pairs, two trained annotators, agreement ≥0.75 and alpha ≥0.67, or human-primary fallback. Out-of-repository blinding seeds/keys or isolated exported packets prevent unblinding through Git (F-31).
9. `uv run --locked sib report --run-dir RUN` writes separate derived JSON/Markdown. It discloses numerator/denominator, raw counts/rejections, missingness, all costs/latency, failures, strata, calibration and limits. `uv run --locked sib compare --baseline BASELINE_RUN --candidate CANDIDATE_RUN` compares provenance; use paired statistics for effect estimates. Never claim empirical effectiveness from fake fixtures.
10. Stop on call/cost/concurrency/retry/failure limits, credential leakage, invalid correlation, changed disclosures, corrupted accounting, failed calibration, or missing approval. Preserve failures/refusals as outcomes. Do not overwrite evidence to repair a run. Verify and retain the failure; use a new run/version when inputs change. Escalate unresolved dispatches and custody failures to the operator.

Private packs remain outside public Git and automatic agent context. `sib validate-pack --restricted-pack PACK --split validation` gives counts/digests only. Detailed restricted declarations, keys, raw records, storage paths and approvals remain in controlled external storage. `sib restricted-preflight --declaration DECLARATION --output AUTHORIZATION` records authorization only from the reviewed checkout. Public CLI execution remains development-only. Validation may return only release eligibility to candidate developers; sealed testing ends in reporting and stop. Contaminated cases must be retired and replaced before future development use.

Any proposed candidate skill changes require a separate branch, candidate version, approved behavioral amendment if needed, and full public-development gates.
