# Restored-candidate development investigation

This is an execution/evidence record, not a behavioral authority. The approved
specifications and canonical skill govern. Starting revision: `a36903a`; existing
branch: `stress-test/five-cycle-refinement`; initial worktree clean.

## Scope and stopping

1. Freeze the starting five-file pack, exact prompts, public cases, settings and
   measurement source hashes. Audit extraction with equivalent layouts and
   non-proposals; retain misses and false positives. Repair only demonstrated
   measurement bugs, identically for all arms.
2. Probe the installed CLI and its cumulative usage semantics before trusting
   token efficiency. Retain raw events, failures and unavailable measurements.
3. Run a small public development diagnostic with clean, creative, format-matched
   and full-pack conditions. No rubrics or answer keys go to generators.
4. Test each verified instruction contradiction with a minimal reproducer;
   change one component at a time, retain before/after responses, and rerun
   affected cases twice where transport is available.
5. Reserve public development holdout prompts before edits; use them only for a
   final check. Produce blinded human-review inputs, leaving quality scores and
   the primary effect unknown until independently calibrated.
6. Run the requested full unit suite, validator, authority/reference/size checks
   and diff check. Update CONTEXT.md and commit verified changes. No push,
   merge, release, restricted-pack access or full development study.

The benchmark package and formal six/twelve-case gate machinery do not yet
exist. This bounded diagnostic cannot pass those gates or unlock the 60-case
study. Formal feasibility and human calibration remain explicit dependencies.

## Planned resource ceiling (before any call)

- Model: `gpt-5.6-luna`, installed CLI `0.162.1`, ignored user config/rules,
  read-only sandbox, isolated working root, no requested research or tools.
- Protocol probe: at most 3 assistant calls.
- Initial diagnostic: at most 64 assistant calls across four arms, including
  ordered four-turn interaction, one repeated broad case, and all requested
  boundary categories. One initial repetition except the repeated broad case.
- Behavioral corrections: at most 36 calls, two fresh replicates per affected
  reproducer when possible; no ablation or efficacy attribution.
- Final public holdout: at most 8 calls, four arms, once, after candidate freeze.
- Hard ceiling: 111 assistant calls; concurrency at most 3; no automatic retry.
  Stop transport attempts after two consistent infrastructure failures. Monetary
  cost is unknown; this is a call/time ceiling, not a dollar guarantee.

No repetition expansion for statistical claims until case-level variance and
human calibration are available. Each prompt's script and resources are shared
across arms. Report absolute breadth and all-turn costs beside efficiency;
unrated quality gates and useful distinct mechanisms remain null.

## Investigation leads

- Two-exchange discovery stop versus sufficient-context/seven-question rule.
- Four-line compact default and budget truncation called saturation.
- Same lever/stage equality versus causal/structural distinctiveness.
- Missing brief, ledger, portfolio and receptivity fields.
- Duplicate Python test methods and source/project provenance conflation.

Competing explanations for behavioral differences include stochastic generation,
case difficulty, output layout, model instruction following, and host context.
Textual conflicts alone do not establish their observed behavioral effect.
