# Systematic Innovation

## Core Principle

Genuine innovation requires **causally distinct mechanisms** connected to **systemic realities and human receptivity**—not surface-noun variations of the same default trope. Every possibility must change *how* the system produces outcomes while protecting what already works.

## When Not to Trigger

Do **not** run this workflow when the user asks for:
- Factual definitions, historical explanations, or textbook comparisons (answer directly).
- Debugging, root-cause diagnosis of a specific technical defect, or performance micro-benchmarks.
- Implementation artifacts for an already-selected solution (such as database schemas, sprint tickets, or code).
- Evading audits, hiding safety/regulatory findings, avoiding detection, or breaking statutory, privacy, life-safety, or medical-safety obligations. Refuse the bypass intent; offer compliant alternatives only if the user explicitly changes the target.

## Mode Routing (Quick vs. Deep)

Route automatically using observable signals in the user's request unless the user explicitly overrides the mode:

| Route | Observable Prompt Signals | Behavior |
| :--- | :--- | :--- |
| **Quick Mode** | Single-actor personal system, bounded feature or operational bottleneck, one-turn/single-turn/API execution, explicit request for immediate options or a single lens, or user says `"skip questions"` / `"give me ideas now"`. | Build a compact Innovation Brief and System & Preservation Scan from the prompt, run System Dynamics plus two selected Reasoning Cells after initial fluency depletion, and deliver **10 to 15 distinct possibilities** in one turn. |
| **Deep Mode** | An actual interactive multi-turn channel is available, and a multi-stakeholder organizational, civic, educational, or cross-departmental system has hidden incentives, unstated preservation boundaries, or competing goals. | Run the System & Preservation Scan, ask **one question at a time** (never more than seven total) paired with **2–3 contrasting provisional seeds**, then synthesize **15 to 24 distinct possibilities** once context is disclosed. |

### Execution-Channel Precedence

1. An explicit user override has the highest precedence.
2. If the request must be answered in one turn—single-turn, one-shot, API response, immediate output, or no user reply is available—deliver a complete portfolio now even when the substantive problem is complex. Record unresolved assumptions in Layer 1 and do not stall in discovery questions.
3. Deep Turn-1 restraint is valid only when the actual channel permits a user reply or the user explicitly requests progressive discovery. Never infer it from organizational, civic, or cross-domain complexity alone.
4. If the user requests Deep Mode but only one response is available, produce the complete portfolio with an explicit assumption and preservation ledger.

### Hard Output Budget Precedence

A requested maximum word or token budget overrides normal candidate counts and formatting. Target **80% of the requested ceiling**, and for a word ceiling of 500 or fewer use the `Compact Portfolio Template` in [output-contract.md](references/output-contract.md). Do not add introductions, explanations, or formatting that consume the budget.

### User Overrides
- `"Use Quick mode"`, `"skip questions"`, or `"Produce your final portfolio now"` $\rightarrow$ skip further questions and output the complete portfolio immediately.
- `"Use Deep mode"` $\rightarrow$ run progressive discovery before locking the portfolio.
- `"Use Provocation mode"` $\rightarrow$ **Provocation mode requires Contrarian and Boundary Reframing** as primary generators with explicit safety and feasibility extraction.

## The Innovation Brief & Preservation Scan

Before generating possibilities, establish five brief fields (explicitly in Deep Mode; concisely in Quick Mode):

1. **Perceived Mess vs. Operational Tension:** What symptom is being reported versus what structural conflict keeps recreating it?
2. **System Actors & Boundary Overflows:** Who owns the problem, who bears the friction, and which adjacent teams or external actors are affected?
3. **Preservation Inventory (What Works & Must Remain):** Which existing incentives, statutory reviews, safety/privacy floors, or cultural strengths must **not** be broken?
4. **Unlocked Levers vs. Hard Constraints:** What can be re-sequenced, re-bundled, or inverted within current budget, staffing, and legal guardrails?
5. **Initial Fluency Depletion (Memory-Dump Quarantine):** List the 2–3 most obvious default tropes for this domain and set them aside so the portfolio explores non-obvious causal mechanisms.

### Preservation Across Turns

Carry forward a cumulative `Preserve:` ledger of every explicit invariant, including earlier user turns. Later examples, seeds, convenience, or silence never revoke it. When a new disclosure conflicts with a seed, withdraw or revise that seed and recheck every final candidate against the cumulative ledger. If a later request would weaken safety, rights, or physical constraints, surface the conflict rather than silently replacing the earlier boundary.

## Reasoning Cell Selection & Mechanism Ledger

Quick Mode uses **System Dynamics plus two selected Reasoning Cells**. Deep Mode uses **five or six selected Reasoning Cells** matched to the tension (see [innovation-lenses.md](references/innovation-lenses.md)):

- **System Dynamics:** Change feedback, dependencies, delays, or leverage points.
- **Human Value:** Reconfigure needs, behavior, accessibility, trust, dignity, or participation.
- **Operational Reality:** Remove friction, bottlenecks, workarounds, or hidden labor.
- **Boundary Reframing:** Change the objective, scope, ownership, or assumed limits.
- **Mechanism Transfer:** Import a causal mechanism from a structurally relevant outside domain.
- **Contrarian:** Reverse one named assumption and trace the consequences.
- **Futures:** Change time, scale, scarcity, technology, or institutional conditions.

### Distinctiveness & Saturation Rules
1. Track every candidate in an explicit **Mechanism Ledger** across four structural dimensions:
   - **Changed Variable / Object**
   - **Causal Lever Type** (e.g., temporal inversion, boundary re-partition, incentive unbundling, physical poka-yoke, subtraction/sunset, information schema unification, peer/ecosystem co-production)
   - **Timing / Stage of Action** (upstream pre-condition, point-of-action, in-transit, post-event audit)
   - **Feedback Loop Altered**
2. **Duplicate Test:** If two ideas use the same causal lever at the same stage with different nouns or channels (e.g., a QR code flyer, a shelf tag, and a checkout card all signaling donor need at a store), **merge them into one mechanism family**.
3. **Saturation Stop:** These are targets, not quotas. Stop adding options after a targeted transformation pass yields zero or one new mechanism; if a narrow problem saturates below the target, say so rather than padding variants.

## Ideation-Only & High-Stakes Guardrails

- **No Premature Winner or Implementation Drift:** Keep the portfolio open. Do **not** append unrequested 30-60-90 day rollout roadmaps, Gantt schedules, sprint backlogs, database schemas, pilots, or experiments. Only when the user explicitly requests experiments, provide bounded, falsifiable probes.
- **No Fabricated Statistics:** Never invent quantitative percentages or effect sizes inside examples. Label causal predictions as testable hypotheses.
- **High-Stakes Safety Floor:** Never propose bypassing statutory life-safety reviews, child/student safeguarding, medical dosing safety, or patron/user privacy.
- **Physical/Logical Constraint Floor:** If stated constraints are jointly impossible, identify the contradiction and re-anchor the boundary. Never manufacture fake compliance by inventing inventory, authority, energy paths, legal exceptions, or hidden mechanisms.

## Reference Navigation

Read the following reference files conditionally based on the active phase of work:
- Read [innovation-lenses.md](references/innovation-lenses.md) when selecting Reasoning Cells, applying initial fluency depletion, running multiple redefinition or synectic excursions, or deduplicating the Mechanism Ledger.
- Read [deep-mode.md](references/deep-mode.md) when an organizational or multi-stakeholder challenge triggers Deep Mode progressive questioning or when handling mid-stream context disclosures.
- Read [output-contract.md](references/output-contract.md) when formatting the six-layer response, evaluating Rickards's Three Problem-Owner Questions, routing across Mission-Orientated / Negotiative / Participative boundary modes, or inoculating against *Yes-but* rejection.

# Included reference: innovation-lenses.md
# Innovation Lenses, Reasoning Cells & Mechanism Ledger

The named Reasoning Cells are a **Project-original AI-native mechanism**. Their internal lenses draw on verified principles and adapted creative-problem-solving methods; neither the cell taxonomy nor its labels should be attributed to Tudor Rickards.

## 1. Initial Fluency Depletion (Countering RLHF Homogenization)

Rickards's work on initial fluency and later LLM ideation studies motivate checking familiar associations before structural transformation. The quarantine procedure below is an AI-native adaptation, not a universal empirical claim about the first few ideas.

Before populating the portfolio:
1. **Name the Default Tropes (1–2 lines):** Explicitly state the 2–3 most predictable textbook or internet answers for the prompt (e.g., *"Standard reminders / gamified streaks / NFC cap stickers"*).
2. **Quarantine or Compress:** Either set those tropes aside entirely or compress them into a single baseline benchmark note so that the numbered portfolio explores distinct, higher-leverage mechanisms.

## 2. The Seven Reasoning Cells

Quick Mode uses **System Dynamics plus two selected Reasoning Cells**. Deep Mode uses **five or six selected Reasoning Cells**. Each selected cell produces **Two to four candidate mechanisms**, their intervention point, a concise causal explanation, and a distinction from mechanisms already present.

### System Dynamics
Change or exploit feedback, dependencies, delays, and leverage points. Map stocks, flows, accumulation, and the point where a small structural shift can change the system's behavior.

### Human Value
Reconfigure needs, behavior, accessibility, trust, dignity, or participation. Use empathic and motivational reframing to find hidden labor, exclusion, anxiety, or status loss that a process-focused idea would miss.

### Operational Reality
Remove friction, bottlenecks, workarounds, repeated handling, and hidden labor. Reuse existing byproducts, idle capacity, or mandatory touchpoints without adding undisclosed staff, equipment, permissions, or cost.

### Boundary Reframing
Change the objective, scope, ownership, or assumed limits. Apply multiple redefinition modes—analytic, empathic, motivational, metaphorical, and boundary-relaxed—before generating mechanisms.

### Mechanism Transfer
Import a causal mechanism from a structurally relevant outside domain. Translate the abstract causal graph (e.g., custody handoff, perishable inventory, multi-authority veto), never merely the vocabulary or metaphor.

### Contrarian
Reverse one named assumption and trace the consequences. Formal provocation may be used as a stepping-stone, but every raw provocation must be translated into a constraint-compliant, safe operational mechanism.

### Futures
Change time, scale, scarcity, technology, or institutional conditions. Test whether a mechanism remains useful when demand, capability, cost, regulation, or coordination conditions shift.

## 3. Parallel Execution & Sequential Fallback

When independent sub-contexts are available, selected cells may run in parallel and return candidate mechanisms with explicit ledger coordinates. Otherwise, one model performs sequential contrastive passes and never claims those passes were independent agents.

## 4. The Mechanism Ledger & Duplicate Collapse Test

Every portfolio must include or enforce a compact **Mechanism Ledger** proving that each numbered possibility occupies a distinct structural coordinate:

| Possibility ID | Cell / Lens | Changed System Variable | Causal Lever Type | Stage of Action | Feedback Loop Shifted |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `P1` | ... | ... | ... | ... | ... |

Before finalizing, compare every pair of candidates:
1. **Same lever + same stage = merge:** Merge wording variants into one richer mechanism family.
2. **Minimum quality gate:** Every candidate must be relevant, constraint-aligned, causally clear, plausible, and safe.

## 5. Adversarial Feasibility and Preservation Check

Before recording a candidate, enumerate the resources it consumes and the authority it needs. Distinguish supplied inventory from a newly required resource; never smuggle in extra materials, equipment, staff, consent, or permissions through an analogy. Check geometry and capacity as well as labels. Label unknown dimensions and operating conditions rather than asserting feasibility.

On every new user disclosure, revisit all earlier preservation commitments. Re-test the actual causal chain, not just its `Preserve check` sentence. A nominally compliant candidate that adds hidden workload, transfers a burden to an unconsenting actor, or weakens a preserved service is a revision or rejection. Regulatory evasion and concealment are prohibited targets.

# Included reference: deep-mode.md
# Deep Mode: Progressive Discovery, Provisional Seeds & Contested Boundaries

## 1. When Deep Mode Activates

Actual interaction availability is mandatory for Deep Turn-1 restraint. Never activate Deep Mode Turn-1 restraint solely because the challenge is multi-stakeholder, civic, organizational, or high-risk. If the request is a single-turn request or otherwise permits no user reply, produce a complete portfolio with an explicit assumption and preservation ledger.

Activate Deep Mode when the user's challenge involves:
- Multiple interacting roles, departments, or external stakeholders whose incentives pull in opposite directions.
- High risk of breaking something that already works (e.g., individual sales ownership, statutory safety/public accountability, regulatory compliance, teacher autonomy, or patron privacy).
- Ambiguous ownership boundaries where a naive solution would fail immediately due to resource limits or organizational resistance.

## 2. One Question at a Time & the Seven-Question Ceiling

In our RED baseline study, vanilla models asked **zero discovery questions on Turn 1** across 100% of Deep cases and immediately proposed ideas that violated unstated payroll, statutory, or staffing constraints. Batching questions, however, creates friction and invites partial answers. Deep discovery therefore obeys four rules:

1. **The Question-Value Filter:** Only ask a question if the answer will **eliminate or unlock an entire causal family of mechanisms**. Never ask generic background questions that do not change the solution structure.
2. **Ask exactly one decision-relevant question per discovery turn.** Do not batch discovery questions. Ask the highest-leverage unknown, wait for the answer, then decide whether another question is justified.
3. **Never exceed 7 total questions across the entire session.** Stop earlier when the answer cannot change the portfolio. A one-shot request must receive the complete portfolio, not this discovery sequence.
4. **Target the Four High-Leverage Unknowns:**
   - **Preservation Boundary:** *"What part of the current system works well and must remain untouched?"*
   - **Failure Localization:** *"Where specifically does the handoff, information flow, or incentive break down today?"*
   - **Resource & Authority Envelope:** *"Which levers (sequencing, routines, intake, partnerships) can you change directly versus which (payroll, headcount, statutory rules) are fixed?"*
   - **Safety & Equity Floor:** *"What non-negotiable safety, privacy, or equity standard must every option protect?"*

## 3. Contrasting Provisional Seeds on Early Turns

Never return a bare question without immediate value. On each discovery turn, pair the single question with **2–3 Contrasting Provisional Seeds**:
- Each provisional seed is a **2–3 sentence structural sketch** showing how the solution direction will branch depending on the user's answers (e.g., *Seed A: Incentive/Attribution Unbundling* vs. *Seed B: Asynchronous Physical/Artifact Handoff* vs. *Seed C: Upstream Subtraction/Triage*).
- Keep provisional seeds compact (**under 350 tokens total on Turn 1–2**) so token budget is reserved for the final synthesized portfolio once constraints are confirmed.

## 4. Stopping Rule & Immediate Synthesis Triggers

Stop asking questions and produce the complete **Six-Layer Innovation Portfolio** immediately when any of the following occurs:
1. The user provides the preservation boundary, core failure points, and authority/resource constraints.
2. Two discovery exchanges have occurred.
3. The user explicitly instructs: *"Produce your final portfolio now"*, *"Skip questions"*, or *"Use Quick mode"*.

## 5. Cumulative Preservation and Revision

Keep the preservation ledger cumulative across all turns, including after an early synthesis. Repeat its material constraints in the final brief and check each candidate's resource demand and causal chain against it. New disclosures can invalidate a seed; explicitly retire or revise the affected seed. Never treat the newest message as permission to forget an earlier invariant.

# Output Contract, Disclosure Layers & System Receptivity

## 1. The Six Disclosure Layers

**Budget precedence:** A hard word or token ceiling in the user request overrides normal verbosity. For a word limit, draft internally to **min(80% of the stated word ceiling, 250 words)**, count every visible word including headings, and revise before sending. Produce a compressed six-layer response using an ultra-compact format: Layer 1 at most 40 words; four candidate lines with intervention, causal chain, causal lever, and Preserve check, each candidate at most 30 words; one-line receptivity; two spotlight signals; and user-directed continuation. Never exceed an explicit visible word ceiling. If the ceiling cannot fit four candidates, stop at the largest number that fits and state saturation.

### Compact Portfolio Template

For a requested word ceiling of 500 or fewer, use exactly this plain-text structure and stop. This template supersedes the normal Six Disclosure Layers formatting. Each candidate line at most 30 visible words including labels; omit optional assumption and failure prose. `L1: ...` (tension, preservation, assumptions); `P1: ... | Intervention: ... | Causal chain: ... | Causal lever: ... | Preserve check: ...` through the candidates that fit; `L4: ...` (receptivity and action boundary); `L5: ...` (connections and tensions); `L6: ... (user-directed continuation; no automatic experiments)`. No Markdown tables, headings, or bold styling. Allocate at most 40 words to L1, 120 total to candidates, 30 total to L4–L5, and 30 to L6. These are maxima, not quotas. Count visible words before sending and remove any excess.

Structure every final innovation portfolio (both Quick Mode single-turn responses and Deep Mode final synthesis turns) into six clear, scannable layers:

### Layer 1: Innovation Brief
- **Core Tension:** 1–2 sentences contrasting the surface symptom with the underlying structural contradiction.
- **Preservation Inventory (What Must Remain Intact):** Bullet the specific strengths, incentives, statutory reviews, or privacy/safeguarding floors that every option below protects.
- **Assumptions:** Name the material inferences used when context is incomplete.
- **Quarantined Default Tropes (Initial Fluency Depletion):** Explicitly name and set aside the 2–3 obvious textbook/internet tropes so the portfolio below focuses on non-obvious causal mechanisms.

### Layer 2: System Snapshot
Identify actors, incentives, dependencies, existing strengths, failed approaches, constraints, leverage points, friction, rework, and boundary overflows. Include a compact mechanism-ledger view when it helps prove structural distinctiveness:
- `ID & Title` | `Reasoning Cell` | `Intervention point` | `Changed System Variable` | `Causal lever` | `Stage of Action` | `Feedback Loop Shifted`

### Layer 3: Complete Portfolio
- **Quantity Targets & Saturation Stop:** These are targets, not quotas.
  - **Quick Mode:** **10 to 15** causally distinct possibilities.
  - **Deep Mode:** **15 to 24** causally distinct possibilities.
  - **Saturation Rule:** Stop when one targeted transformation pass yields zero or one new mechanism. If a narrow problem saturates below the target, say so rather than padding variants.
- **Required Fields per Possibility (`P1`..`Pn`):**
  - **Descriptive Tag** (non-quota orientation label such as *Temporal Inversion*, *Boundary Re-Partition*, *Subtraction Compact*, *Artifact Poka-Yoke*, or *Ecosystem Co-Production*).
  - **Intervention point:** Where the mechanism acts in the system.
  - **Causal chain:** How the intervention alters system behavior step by step (`Trigger/Rule Change` $\rightarrow$ `Actor Incentive/Flow Shift` $\rightarrow$ `Measurable System Effect`).
  - **Causal lever:** The structural operation changing behavior.
  - **Preserve check:** A candidate-by-candidate statement showing it respects every Layer 1 preservation invariant and each exact budget, staffing, statutory, physical, or privacy constraint. Under a word ceiling, use `Preserve check: all L1 invariants` only after Layer 1 lists them explicitly.
  - **Key Assumption & Failure Mode:** What must hold true for this mechanism to work, and what perverse incentive or edge case to watch for (never fabricate statistics or fake percentages).

### Contradiction & Boundary Re-Anchor

If the constraints are jointly impossible, Layer 1 must state the governing contradiction and Layer 5 must expose decision choices. Do not number boundary relaxations as Possibility Portfolio candidates. Instead, use a short re-anchor table: original boundary, why compliance fails, smallest relaxation, and decision owner. Say clearly: **no compliant candidate exists** when that is true.

### Layer 4: Possibility Spotlights
Develop **five to seven** possibilities representing different signals rather than finalists. Include at least these signals where the portfolio supports them: strongest strategic fit, boldest departure, lowest structural friction, highest potential upside, most important uncertainty, best hybrid, and most revealing reframing. For each spotlight, add concise receptivity:
1. **The Three Problem-Owner Questions (Rickards 1985, p. 160):** new to the problem owner, mission relevance, and resource actionability.
2. **Boundary mode (Rickards 1985, pp. 159–163):** mission-orientated, negotiative, or participative.
3. **Yes-But Inoculation:** the likely objection and the safeguard that preserves the core mechanism.

### Layer 5: Connections and Tensions
Identify compatible combinations, mutually exclusive approaches, shared dependencies, conflicting assumptions, and possibilities that could form a broader system. Do not declare a mandatory winner.

### Layer 6: User-Directed Continuation
Offer the user explicit next choices: expand a possibility, compare selected possibilities, combine mechanisms, challenge an assumption, generate another cell pass, or request experiments. No experiment, pilot, rollout, or implementation plan appears automatically.

## 2. Requested Experiment Contract

Only when the user explicitly requests experiments, propose **one to three concrete, reversible experiments** to test the riskiest causal assumptions using existing resources. If the user explicitly requests experiments under a hard output ceiling, replace L6 with the largest number of experiment lines that fit. Each experiment must contain:
- Observable metric.
- **quantitative disconfirmation threshold** chosen as a decision rule.
- **sample or observation bound**.
- **time horizon**.
- Explicit **fallback next move**.

Reject or revise the mechanism if the threshold is not met; do not continue because the pilot felt promising. Thresholds are prospective decision rules, not claimed historical effects. Do not generate multi-month 30-60-90 day rollout schedules, project-management roadmaps, sprint ticket backlogs, or database DDL inside an ideation portfolio.
